## Phase 0：环境搭建（2026-06-07~08）

### 平台迁移决策

**结论**：MonoGS 必须在 Linux 下运行，Windows 不可用。

**根因**：MonoGS 使用 Python `multiprocessing` 在前端（Tracking）、后端（Mapping）、GUI 三个进程间共享 CUDA 张量。Linux 使用 `fork` 模式，子进程直接继承父进程内存空间，CUDA 张量的视图引用（view）自然有效。Windows 只能使用 `spawn` 模式，需要 pickle 序列化传递对象，`Camera` 对象中的旋转矩阵 `R` 是 `torch` 视图张量（view tensor），pickle 后其 base storage 引用断裂，`R[1,1]` 变为 0，导致 `linalg.inv` 奇异矩阵崩溃，报 `LinAlgError: singular matrix`。这是架构层面的不兼容，无法通过调参解决。

### 缺陷B：高斯各向异性过度拉伸

**缺陷机理**

MonoGS 中每个高斯的形状由协方差矩阵 **Σ** = **RSS**ᵀ**R**ᵀ 描述，其中对角矩阵 **S** = diag(s₁, s₂, s₃) 为三轴尺度参数。MonoGS 对 s₁, s₂, s₃ 不施加任何约束，优化器完全自由地调整各轴比例。

在低纹理平面（白墙、桌面）处，优化器的"最小阻力路径"是将高斯沿观测**视线方向**极度拉伸：单个高斯在 2D 投影面积最大化，快速降低当前训练视角的渲染损失，但代价是从偏离训练视角观察时，该高斯几乎消失，导致新视角渲染出现条状空洞。

MonoGS 原论文已引入各向同性正则化损失 E_iso（λ_iso=10），但其约束形式为对三轴均值的偏差求和，无法区分"沿表面拉伸"（合理）和"沿视线拉伸"（有害）两种不同性质的各向异性，在单目模式下约束效果有限。

**量化证据**（提取全部高斯的 scaling 参数，计算 s_max/s_min）：

| 指标 | 数值 |
|------|------|
| 平均拉伸比（s_max/s_min） | **155.52×** |
| >10× 占比 | **31.8%**（3,824 / 38,264 个） |
| >50× 占比 | **13.2%** |
| 分布图 | `results/tum_freiburg3/2026-06-08-22-35-07/aniso_distribution.png` |

**改进假设**（可证伪形式）：  
若在 mapping 损失中加入对视线方向拉伸的惩罚项，区分视线方向各向异性（有害）与表面方向各向异性（合理），则在 TUM fr3/office 上 ATE 下降 ≥5%，Replica room0 上 LPIPS 下降 ≥0.005。

### 缺陷D：历史关键帧离开窗口后完全失去梯度监督

**缺陷机理**

MonoGS 的 mapping 每次优化当前滑动窗口内的帧（TUM: N=8，Replica: N=10）。一帧被踢出窗口后，它覆盖的空间区域在后续所有 mapping 迭代中**完全接收不到梯度信号**。优化器在这些区域上无任何约束，对应高斯会随其他区域的优化逐渐漂移，在渲染时产生几何空洞或条状伪影。

这与缺陷A（窗口内残差不均衡）是不同层次的问题：
- 缺陷A（已探索，改进失败）：窗口内部，哪些帧占位
- 缺陷D（本改进方向）：窗口外部，已离开窗口的帧所覆盖区域从此零约束

**与改进A的关键区别**：改进A试图修改踢帧逻辑，破坏了 OC 几何约束导致失败。改进D **完全不修改窗口逻辑**，只在 mapping 的 viewpoint 采样中额外插入历史帧——tracking 使用的帧集合不变，OC 几何约束完全保留。

**量化证据**（对窗口外历史帧随机抽样，计算渲染 L1 loss，与窗口内帧对比）：

| 阶段（iter） | 窗口内帧平均残差 | 历史帧平均残差 | 差距 |
|------------|--------------|-------------|------|
| ~5,000 | 0.048 | 0.061 | 1.3× |
| ~10,000 | 0.035 | 0.067 | 1.9× |
| ~15,000 | 0.028 | 0.079 | 2.8× |
| ~19,800 | 0.025 | 0.088 | **3.5×** |

历史帧渲染残差随训练推进持续上升，而窗口内帧残差受优化约束保持受控，两条曲线的差距随时间扩大。这直接证明历史帧覆盖区域的高斯在失去监督后持续退化。

分布图：`results/tum_freiburg3/2026-06-08-22-35-07/historical_frame_residual.png`

**改进假设**（可证伪形式）：  
若每隔 K 次 mapping 迭代从历史帧池随机抽取一帧加入当次优化，则历史帧覆盖区域的高斯持续获得梯度监督，在 TUM fr3/office 上 PSNR 提升 ≥0.3 dB，ATE 变化幅度 ≤5%。

### 缺陷说明（B 与 D 的独立性）

| 维度 | 缺陷B（各向异性） | 缺陷D（历史帧零监督） |
|------|-----------------|-------------------|
| 问题层次 | 单帧几何约束（每个高斯的形状） | 时序覆盖（历史区域的持续监督） |

两者机理正交，均不属于原论文明确承认并已修复的局限（原论文承认的局限是"无回环检测"和"未达30fps实时"）。

## Phase 3：改进A — 自适应关键帧窗口（全部失败）

### 探索目标

基于缺陷A的观测（窗口内残差不均衡），假设引入渲染残差信息辅助踢帧决策，可以提升关键帧窗口的信息利用效率。

### 四次探索与失败分析

| 方案 | 踢帧策略 | TUM ATE | 变化 | 失败根因 |
|------|---------|---------|------|---------|
| Baseline | OC 最低帧 | 3.35 cm | — | 基准 |
| 方案A（L1残差最低） | 踢渲染残差最低帧 | 4.27 cm | +27% | 白墙帧L1天生低，残差低≠几何已收敛 |
| 方案B（残差变化率） | 踢残差不再下降的帧 | 4.72 cm | +41% | 优化停滞≠已收敛，仍有约束价值 |
| 方案A1（OC+残差双条件） | OC排序+残差二次确认 | 6.30 cm | +88% | 阈值0.05过松，退化为带噪声的OC策略 |

### 核心洞察

> **OC（共视重叠度）的几何约束是单目 GS-SLAM tracking 的必要条件，不可被渲染残差信息替代或补充。**

在单目 SLAM 中，相机位姿估计完全依赖与当前帧有几何共视关系的历史帧。OC 直接量化这种几何关系。任何偏离 OC 优先级的踢帧策略，都会破坏 mapping 对 tracking 的几何约束，导致 ATE 退化。

这个结论是通过四组递进实验系统性证伪得出的，与改进C的失败共同指向同一更深层结论：MonoGS 的性能瓶颈在于光度误差精度本身，资源分配策略（窗口选择、密度化）的调整均无法突破这一限制。

**对报告的价值**：四次失败的递进探索过程构成 Discussion 章节的高质量内容，直接体现"过程性思考"。

## Phase 4：改进B — 各向同性正则化

**修改文件**：`utils/slam_backend.py`（新增 `isotropic_loss_view_aware()`；在 `map()` loss 后追加，通过配置开关控制）

### 方案演进

#### B1：全局惩罚（λ=0.01）❌

```
L_iso = λ × mean(s_max/s_min − 1)
```

| 指标 | Baseline | B1 | 变化 |
|------|---------|-----|------|
| TUM ATE | 3.35 cm | 4.45 cm | +33% ⚠️ |
| TUM LPIPS | 0.350 | 0.397 | +13% ⚠️ |
| TUM 拉伸比 | 155× | 1.37× | ↓99% ✅ |
| Replica ATE | 0.44 cm | 0.41 cm | −7% ✅ |

**失败分析**：约束过强，强制所有高斯接近球形，破坏了"沿表面方向拉伸"这一合理的高效表示。优化器需要用更多小球覆盖平面，梯度信号被稀释，tracking 精度下降。**一刀切约束无法区分合理拉伸与有害拉伸。**

#### B2：全局惩罚（λ=0.005）❌

TUM ATE 75cm（tracking 发散），拉伸比 284×（比 baseline 还高），LPIPS 0.439。

**失败分析**：λ=0.005 约束太弱，几乎不生效。λ=0.005 与 0.01 之间不存在有效区间，说明**问题在于约束形式本身，而非 λ 取值**。

#### B3：阈值截断（T=5）✅

```python
ratio = s_max / (s_min + 1e-6)
L_iso = λ × clamp(ratio − T, min=0).mean()
# ratio ∈ [1, T]：合理拉伸，不惩罚
# ratio > T：极端拉伸，才施加惩罚
```

| 指标 | Baseline | B3 | 变化 |
|------|---------|-----|------|
| TUM ATE | 3.35 cm | **3.28 cm** | −2.1% ✅ |
| TUM 拉伸比 | 155× | **3.29×** | ↓98% ✅ |
| TUM LPIPS | 0.350 | 0.365 | +4.3% ⚠️ |

**改进**：T=5 允许合理的平面拉伸，只惩罚极端情况。ATE 改善，但 LPIPS 仍轻微退化——说明阈值截断策略仍未能有效区分视线方向拉伸与表面拉伸。

#### B4：视线方向感知（最终方案）✅

**核心思路**：不同方向的各向异性危害程度不同。沿**相机视线方向**的拉伸是有害的（从侧面看几乎消失）；沿**场景表面方向**的拉伸是合理的（高效覆盖平面）。对拉伸方向与视线方向的夹角余弦加权惩罚，使约束自动集中在有害拉伸上。

```python
def isotropic_loss_view_aware(gaussians, camera_pos, lambda_iso=0.01):
    scales = gaussians.get_scaling          # [N, 3]
    rotations = gaussians.get_rotation      # [N, 4] quaternion
    
    # 最长轴方向（世界坐标系）
    R = quaternion_to_matrix(rotations)     # [N, 3, 3]
    max_axis_idx = scales.argmax(dim=1)     # [N]
    longest_axis = R[torch.arange(N), :, max_axis_idx]  # [N, 3]
    
    # 视线方向（高斯中心 → 相机）
    viewing_dir = F.normalize(
        camera_pos.unsqueeze(0) - gaussians.get_xyz, dim=1
    )  # [N, 3]
    
    # 对齐度：1=平行于视线（有害），0=垂直于视线（合理）
    alignment = (longest_axis * viewing_dir).sum(dim=1).abs()  # [N]
    
    # 各向异性比率
    s_max = scales.max(dim=1).values
    s_min = scales.min(dim=1).values
    ratio = s_max / (s_min + 1e-6)
    
    # 视线方向对齐度加权惩罚
    loss = (alignment * torch.clamp(ratio - 1.0, min=0.0)).mean()
    return lambda_iso * loss
```

| 指标 | Baseline | B4 | 变化 |
|------|---------|-----|------|
| TUM ATE | 3.35 cm | **3.01 cm** | **−10.1%** ✅ |
| TUM PSNR | 22.06 | 22.61 | +0.55 dB ✅ |
| TUM SSIM | 0.761 | 0.772 | +1.4% ✅ |
| TUM LPIPS | 0.350 | 0.358 | +2.3% ⚠️ |
| Replica ATE | 0.44 cm | **0.35 cm** | **−20.5%** ✅ |
| Replica RPE | 0.27 cm | **0.24 cm** | −11.1% ✅ |

**B4 是 ATE 最优方案**，Replica ATE 下降 20.5%，TUM ATE 下降 10.1%。LPIPS 略有退化（+2.3%），推测原因：视线感知约束在某些场景下限制了合理拉伸，牺牲了少量渲染表现力换取几何精度。

## Phase 5：改进C — 自适应密度化（全部失败）

### 探索目标

基于缺陷C的观测（densification 对场景复杂度无差别处理），假设对高残差区域补充密度化驱动可以提升低纹理区域的高斯密度，改善渲染质量。

### C1 证据与死局

残差与 Sobel 图像梯度的 Pearson 相关系数 **r = 0.348**（正相关）。

这个证据本身揭示了改进 C 的根本死局：**高残差的区域，梯度也高**。这意味着 MonoGS 的 densification 机制对这些区域已经有响应——不是因为 densification 忽视了它们，而是这些区域本身难以用更多高斯来拟合（边缘、纹理复杂区域）。

### 实验结果

| 方案 | 设计 | TUM ATE | 变化 | 失败根因 |
|------|------|---------|------|---------|
| C2（梯度增益） | 高残差区高斯梯度增量×3 | 3.89 cm | +16% | 高残差区梯度已高，乘3不影响阈值判断 |
| C3（阈值补足） | 强制高残差区低梯度高斯超过阈值 | 4.97 cm | +48% | 少数低梯度噪声高斯引入，破坏tracking |

### 核心洞察

> **高残差 ≠ 高斯密度不足。**

残差高是因为区域本身难以拟合（精细纹理、边缘），不是因为高斯不够多。加更多高斯不解决根本问题，反而引入噪声。改进A和改进C的失败共同指向同一更深层结论：MonoGS 的瓶颈不在于资源分配策略，而在于光度误差精度本身。

## Phase 6：改进D — 关键帧重放

**修改文件**：`utils/slam_backend.py`（`map()` 函数内，在 viewpoint 采样循环中条件插入历史帧）

### 方案设计

在 `map()` 的 mapping 迭代循环中，以可配置的频率从窗口外历史帧池随机抽取一帧，加入当次优化：

```python
# 历史帧池：窗口外的所有关键帧
replay_pool = [i for i in self.cameras.keys() if i not in current_window]

for iteration in range(mapping_iters):
    if (cfg.get("keyframe_replay", False)
            and len(replay_pool) > 0
            and iteration % cfg.get("replay_freq", 10) == 0):
        cam = self.cameras[random.choice(replay_pool)]
    else:
        cam = viewpoint_stack[randint(0, len(viewpoint_stack)-1)]
    # render → loss → backward 流程不变
```

**关键设计原则**：此修改不涉及 tracking 模块，不修改窗口逻辑，OC 几何约束完全保留。这是改进A失败教训的直接应用——不动窗口本身，只在 mapping 阶段补充监督信号。

### 实验D1：replay_freq=5（20%历史帧占比）⚠️

| 指标 | Baseline | D1 | 变化 |
|------|---------|-----|------|
| ATE | 3.35 cm | 3.81 cm | +14% ⚠️ |
| PSNR | 22.06 | 22.29 | +0.23 dB ✅ |
| SSIM | 0.761 | 0.766 | +0.7% ✅ |
| LPIPS | 0.350 | 0.346 | −1.1% ✅ |
| Gaussian 数 | 38,264 | 30,986 | −19% ✅ |

渲染指标改善但 ATE 退化。分析：20% 的历史帧占比过高，历史帧的位姿与当前场景的优化状态存在时序不一致性，频繁的历史帧梯度轻微干扰了高斯形状优化，间接影响下一帧 tracking。

### 实验D2：replay_freq=10（10%历史帧占比）✅ 最优

| 指标 | Baseline | D1（20%） | D2（10%） | 变化（vs Baseline） |
|------|---------|-----------|-----------|-------------------|
| ATE | 3.35 cm | 3.81 cm | **3.06 cm** | **−8.7%** ✅ |
| PSNR | 22.06 | 22.29 | **22.64** | **+0.58 dB** ✅ |
| SSIM | 0.761 | 0.766 | **0.775** | **+1.8%** ✅ |
| LPIPS | 0.350 | 0.346 | **0.325** | **−7.1%** ✅ |
| Gaussian 数 | 38,264 | 30,986 | 51,522 | +35% |

**D2 是全部实验（B1~B4、D1~D2、改进A所有方案）中唯一四项质量指标全面改善的方案。**

10% 占比找到了最佳平衡点：既为历史帧覆盖区域提供足够的梯度监督（PSNR/LPIPS/SSIM 改善），又不频繁到干扰高斯形状优化（ATE 反而改善 8.7%，推测原因：历史帧约束减少了局部高斯的过拟合，使场景表示更全局一致，tracking 因此更稳定）。
